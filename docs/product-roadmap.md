# 产品功能路线

日期：2026-05-24

目标：把当前图片生成工具推进为可复用、可留存、可运营的图片创作工作台。

## 当前产品能力

已具备：

- 注册、登录、退出
- 文生图、参考图生图
- 连续对话创作
- 局部重绘、扩图、抠图
- 生成历史和详情页
- 灵感模板库
- 用户积分、积分流水
- 兑换码
- 公告中心
- 后台用户、公告、配置、审计日志管理

## 产品判断

当前短板不在“还能接多少 AI 模型”，而在用户资产沉淀和商业闭环：

- 用户每次创作都要重复配置参数。
- 历史记录可看但难管理。
- 模板库可用但不可收藏、不可沉淀个人偏好。
- 积分系统存在，但充值/订单闭环未建立。
- 图片生成过程偏同步，缺少任务队列和状态恢复。

## 市场能力参考

基于 Midjourney、Adobe Firefly、Canva、Leonardo 等平台的公开能力，值得参考的方向：

- 风格资产：Midjourney 支持 Moodboards，用图片集合定义项目风格，并可作为默认个性化配置使用。
- 编辑闭环：Midjourney Editor 和 Adobe Firefly 都强调生成后的局部编辑、背景替换、参考图风格匹配。
- 资产管理：Midjourney Organize 提供搜索、筛选、排序、文件夹、时间线和批量操作。
- 品牌一致性：Adobe Firefly 的 style reference 和 Canva 的 Brand Kit / 模板体系都围绕“多张图保持一致风格”。
- 模板工作流：Canva 的强项不是单次生成，而是把生成图片放进设计模板、社媒尺寸、品牌物料和团队协作。
- 实时创作：Leonardo 一类工具强调实时画布、参考图、角色/风格一致性和快速迭代。

对当前产品的启发：

- 先做“可复用的创作资产”，再做“复杂编辑器”。
- 灵感模板需要从静态 prompt 变成可填写的参数化模板。
- 历史记录需要继续升级为项目资产库，支持批量、标签、文件夹和参数复用。
- 商业化前要补齐订单闭环和任务队列，否则增长后体验和客服压力都会上升。

## 版本规划

### V1：复用和留存

已实现。

- 默认创作设置：默认比例、质量、张数、格式、背景、审核等级。
- 历史搜索和筛选：按提示词、模式、收藏状态筛选。
- 历史收藏：本地收藏重点作品，便于后续复用。
- 模板收藏：收藏常用模板，只看收藏模板。
- 模板参数填写：识别模板中的参数占位符，填写后生成最终提示词。

验收标准：

- 用户能在设置页保存默认创作参数。
- 工作台新建创作时自动带入默认参数。
- 历史页支持搜索、模式筛选、收藏筛选。
- 灵感库支持收藏模板和查看收藏模板。
- 带参数模板可以先填写变量，再进入工作台。

### V2：资产管理

本轮实现第一版，不改后端 schema。

- 历史标签：给作品打本地标签，支持按标签筛选。
- 项目文件夹：把作品归到本地文件夹，支持按文件夹筛选。
- 批量选择：历史页进入批量模式，跨当前筛选结果选择多张作品。
- 批量下载：下载所选作品当前封面图。
- 批量删除：删除所选作品；对话链按整条链处理。
- 批量整理：给所选作品批量设置文件夹和标签。
- 参数复制和变体对比：保留到 V2.1。

验收标准：

- 用户能按项目整理图片。
- 用户能快速找到并复用旧作品。
- 用户能对多张图片执行整理、下载、删除。
- 用户刷新页面后，本地文件夹和标签仍保留。

### V3：商业闭环

- 套餐页。
- 充值订单。
- 支付回调。
- 后台订单管理。
- 管理员补单和退款记录。

验收标准：

- 用户能自助购买积分。
- 管理员能追踪订单和积分变化。

### V4：任务队列

- 生成任务表。
- 任务状态：排队、运行、成功、失败、取消。
- 失败重试。
- 前端任务中心。

验收标准：

- 长任务刷新页面后仍可恢复状态。
- 后台能控制并发和失败率。

## 本轮执行范围

实现 V2 资产管理第一版，不引入后端 schema 变更，不接支付，不做队列表。理由：

- V2 先补用户资产整理能力，能直接提升历史作品复用率。
- 改动集中在前端和本地偏好，风险低。
- 后续支付、订单和任务队列需要更完整的数据模型和迁移设计。
