# 平台功能审计与精简建议

日期：2026-05-24

目标：从“图片生成工具”升级为“图片创作平台”，但保持产品克制，优先做能提升复用、留存和商业闭环的功能。

## 当前定位

当前产品已经具备：

- 文生图、图生图、连续对话创作
- 局部重绘、扩图、抠图
- 历史记录、详情页、模板库
- 默认创作偏好
- 本地收藏、标签、文件夹、批量管理
- 积分、兑换码、公告、后台用户和审计

核心问题不是“缺一个模型入口”，而是：

- 生成结果没有完全沉淀为可复用资产。
- 参数、提示词、参考图、风格没有形成项目级工作流。
- 商业闭环还停留在积分和兑换码，没有订单/支付/任务队列。
- 创作工作台能力多，但入口密度高，后续需要拆分和精简。

## 市面平台能力对标

### Midjourney

可参考能力：

- Moodboards：用一组图片形成可复用风格偏好，并可作为默认 personalization 使用。
- Organize / folder：重视作品整理、文件夹和风格资产管理。
- Editor：生成后进入编辑、扩图、局部修改。

对本产品启发：

- 应该把“文件夹/标签”升级成“项目 / 风格板”。
- 历史作品需要保留 prompt、参数、参考图和编辑链路，方便再次生成。

来源：

- https://docs.midjourney.com/hc/en-us/articles/39193335040013-Moodboards
- https://www.midjourney.com/explore

### Adobe Firefly

可参考能力：

- Generative Fill：结合手动选择区域和生成式修改。
- Style/reference：用参考图引导风格一致性。
- 企业侧强调可控、可商用、品牌资产和共享库。

对本产品启发：

- 当前已有局部重绘，但需要把“参考图 + 原 prompt + 编辑结果”串成明确资产链。
- 品牌/项目级默认风格会比单纯多模型更有商业价值。

来源：

- https://helpx.adobe.com/firefly/using/add-objects-in-an-image.html

### Ideogram

可参考能力：

- Canvas：围绕 Generate、Remix、Magic Fill、Extend 组织创作。
- Magic Fill：要求选择局部区域，再结合上下文窗口生成。
- Describe / Remix：让用户从已有结果反推和再变体。

对本产品启发：

- 当前“再次创作”应该更接近 Remix：带回提示词、比例、参考图和关键参数。
- 后续可以加“反推提示词 / 生成相似变体”，但不应先做复杂画布。

来源：

- https://docs.ideogram.ai/canvas-and-editing/canvas/magic-fill
- https://docs.ideogram.ai/canvas-and-editing/canvas/canvas-overview

### Krea

可参考能力：

- Realtime：输入、画布、参考图变化时即时更新结果。
- Enhance：增强、放大和细节重建。
- 多输入源：文字、图片、摄像头、屏幕。

对本产品启发：

- Realtime 是高复杂度功能，当前阶段不建议直接做。
- Enhance / Upscale 更适合作为下一阶段工具能力，能补齐图片后处理闭环。

来源：

- https://docs.krea.ai/user-guide/features/realtime
- https://docs.krea.ai/user-guide/features/enhancer

## 缺失功能分级

### P0：应该优先补

1. 参数复用
   - 从历史和详情页复制 prompt / 参数。
   - 再次创作时带回比例、参考图和可用参数。
   - 原因：这是 Remix、模板化和资产复用的基础。

2. 项目 / 风格板
   - 在现有文件夹基础上升级为项目。
   - 项目内可保存默认比例、常用标签、参考图、风格说明。
   - 原因：比单张图片标签更接近真实生产场景。

3. 生成参数持久化
   - 后端记录质量、张数、格式、压缩率、背景、审核等级。
   - 历史详情展示完整参数。
   - 原因：没有参数持久化，历史复用只能复用 prompt 和比例。

4. 服务端分页和搜索
   - 历史、用户、流水、审计日志不应长期依赖一次性加载。
   - 原因：规模增长后性能和体验都会下降。

### P1：商业化前需要补

1. 套餐页和订单
   - 用户自助购买积分。
   - 订单状态、支付回调、后台补单。

2. 任务队列
   - 任务状态：排队、运行、成功、失败、取消。
   - 支持刷新后恢复。
   - 后台可看失败率和并发。

3. 风格/品牌资产
   - 参考图集合。
   - 品牌色、常用构图、固定提示词片段。

### P2：有价值但暂缓

1. 实时画布
   - 复杂度高，需要专门画布、低延迟模型和任务调度。

2. 视频生成
   - 当前产品链路仍围绕图片，视频会显著扩大存储、计费和任务队列复杂度。

3. 团队协作
   - 需要权限、团队空间、共享资产和审计模型，商业闭环前不优先。

## 需要精简的地方

### 创作工作台

现状：

- 文生图、图生图、对话、工具、编辑入口都集中在 `CreateView.vue`。
- 对新用户来说入口多，理解成本高。

建议：

- 保留顶部模式切换，但每个模式拆成独立组件。
- 高级参数默认折叠，保留当前摘要。
- 工具模式只展示已可用工具，未上线工具不要占主流程。

### 历史资产页

现状：

- 已有搜索、筛选、收藏、标签、文件夹、批量。
- 操作逐渐变多。

建议：

- 卡片只保留：再次创作、复制、整理。
- 删除和下载放在悬浮图标或详情页，避免主操作拥挤。
- 批量模式中保留整理、下载、删除。

### 后台管理

现状：

- 后台能力已经覆盖用户、公告、流水、兑换码、审计。

建议：

- 暂停继续增加后台页面。
- 优先做分页、筛选、导出和操作确认。

## 本轮已处理

- 历史列表增加复制提示词。
- 详情页增加复制参数。
- 再次创作会带回图片比例。
- 工作台 URL 初始化支持更多高级参数：质量、张数、格式、压缩率、背景、审核等级。

按收益排序：

1. 后端 `images` 表增加 generation_params JSON 字段。
2. 详情页展示完整生成参数。
3. 历史列表“再次创作”带回完整参数。
4. 文件夹升级为项目：项目名、说明、默认标签、风格参考。
5. 管理后台分页和历史服务端分页。

## 2026-05-24 追加规划与本轮执行

竞品共性：

- Adobe Firefly 用 Style Kits / Boards 把风格参考、生成约束和团队复用沉淀为资产。
- Canva Magic Studio 的竞争力来自 Brand Kit、模板和发布链路，而不是单次生成。
- Midjourney Moodboards / Organize 强调风格板、文件夹、收藏搜索和再次生成。
- Krea Realtime / Enhancer 强调实时迭代和后处理增强；当前阶段先做 Enhancer/Upscale 更现实。
- Ideogram Canvas / Remix / Extend 强调从已有结果继续，而不是每次重新填 prompt。

本轮选择的落地功能：

1. 完整 Remix / 参数复用。
   - 新生成记录保存 `generationParams`。
   - 历史页和详情页“再次创作”回填比例、质量、张数、格式、压缩率、背景和审核。
   - 旧记录缺少参数时按 prompt + ratio 降级。

2. 默认风格要求。
   - 偏好设置新增 `stylePrompt`。
   - 文生图、图生图、对话创作提交前自动追加默认风格要求。
   - 适合作为轻量 Style Kit / Brand Kit 的第一步。

3. 项目 / 风格板 MVP。
   - 偏好设置可维护多个项目风格板。
   - 每个风格板保存项目名称、说明、默认比例、默认标签和项目风格要求。
   - 创作页可选择风格板，并自动带入比例、风格要求和标签提示。

下一批优先级：

1. 高清增强 / Upscale：历史图进入增强工具，保存为新资产。
2. 项目风格板增强：支持参考图集合和从项目进入历史筛选。
3. 后台列表分页统一：审计、流水、用户管理统一分页体验。
4. 任务队列：生成任务支持排队、运行、失败重试和刷新恢复。

## 2026-05-24 资产库性能迭代

本轮已处理：

- 历史记录接口支持 `limit`、`offset`、`mode`、`q`，返回 `total`。
- 历史页搜索和类型筛选改为服务端查询，避免长期只加载前 50 条。
- 历史页新增分页和每页数量切换，默认每页 24 条。
- `images` store 保持 `fetchImages(50)` 旧调用兼容，同时支持对象参数。
- `ImagesRepo` 增加分页 / 搜索测试，覆盖用户隔离、关键词搜索和 offset。

当前取舍：

- 收藏、文件夹、标签仍保留在当前结果内二次筛选；这是低风险方案。
- 对话链仍按当前页聚合，跨页链路可能不完整；详情页和“从此继续”仍可拿到完整链路。
- 后续如需全量准确的收藏 / 文件夹 / 标签筛选，需要把本地偏好迁移为服务端资产索引。

下一批建议：

1. 高清增强 / Upscale：从历史图片一键进入增强，增强结果作为新资产保存。
2. 项目风格板参考图集合：让项目不只是 prompt 规则，还能保存视觉参考。
3. 对话链列表优化：服务端按 chain 聚合返回首图、尾图、轮次数，避免分页切断。
4. 后台分页体验统一：复用同一套 limit / offset / total 交互。
