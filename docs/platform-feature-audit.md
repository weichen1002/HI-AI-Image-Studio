# 平台功能审计与精简建议

日期：2026-05-24

目标：从“图片生成工具”升级为“图片创作平台”，但保持产品克制，优先做能提升复用、留存和商业闭环的功能。

## 当前定位

当前产品已经具备：

- 文生图、图生图、连续对话创作
- 局部重绘、扩图、抠图
- 历史记录、详情页、模板库
- 默认创作偏好
- 本地收藏、标签、文件夹、批量管理
- 积分、兑换码、公告、后台用户和审计

核心问题不是“缺一个模型入口”，而是：

- 生成结果没有完全沉淀为可复用资产。
- 参数、提示词、参考图和编辑链路还需要更好地复用。
- 商业闭环还停留在积分和兑换码，没有订单/支付/任务队列。
- 创作工作台能力多，但入口密度高，后续需要拆分和精简。

## 市面平台能力对标

### Midjourney

可参考能力：

- Moodboards：用一组图片形成可复用风格偏好，并可作为默认 personalization 使用。
- Organize / folder：重视作品整理、文件夹和风格资产管理。
- Editor：生成后进入编辑、扩图、局部修改。

对本产品启发：

- 应该继续补强“文件夹 / 标签 / 收藏 / 可复用参数”，但不做会全局影响生成的默认风格。
- 历史作品需要保留 prompt、参数、参考图和编辑链路，方便再次生成。

来源：

- https://docs.midjourney.com/hc/en-us/articles/39193335040013-Moodboards
- https://www.midjourney.com/explore

### Adobe Firefly

可参考能力：

- Generative Fill：结合手动选择区域和生成式修改。
- Style/reference：用参考图引导风格一致性。
- 企业侧强调可控、可商用、品牌资产和共享库。

对本产品启发：

- 当前已有局部重绘，但需要把“参考图 + 原 prompt + 编辑结果”串成明确资产链。
- 对平台型生图产品，更通用的价值是参考图、参数复用和资产整理；不应强制抽象为全局风格。

来源：

- https://helpx.adobe.com/firefly/using/add-objects-in-an-image.html

### Ideogram

可参考能力：

- Canvas：围绕 Generate、Remix、Magic Fill、Extend 组织创作。
- Magic Fill：要求选择局部区域，再结合上下文窗口生成。
- Describe / Remix：让用户从已有结果反推和再变体。

对本产品启发：

- 当前“再次创作”应该更接近 Remix：带回提示词、比例、参考图和关键参数。
- 后续可以加“反推提示词 / 生成相似变体”，但不应先做复杂画布。

来源：

- https://docs.ideogram.ai/canvas-and-editing/canvas/magic-fill
- https://docs.ideogram.ai/canvas-and-editing/canvas/canvas-overview

### Krea

可参考能力：

- Realtime：输入、画布、参考图变化时即时更新结果。
- Enhance：增强、放大和细节重建。
- 多输入源：文字、图片、摄像头、屏幕。

对本产品启发：

- Realtime 是高复杂度功能，当前阶段不建议直接做。
- Enhance / Upscale 更适合作为下一阶段工具能力，能补齐图片后处理闭环。

来源：

- https://docs.krea.ai/user-guide/features/realtime
- https://docs.krea.ai/user-guide/features/enhancer

## 缺失功能分级

### P0：应该优先补

1. 参数复用
   - 从历史和详情页复制 prompt / 参数。
   - 再次创作时带回比例、参考图和可用参数。
   - 原因：这是 Remix、模板化和资产复用的基础。

2. 生成参数持久化
   - 后端记录质量、张数、格式、压缩率、背景、审核等级。
   - 历史详情展示完整参数。
   - 原因：没有参数持久化，历史复用只能复用 prompt 和比例。

3. 服务端分页和搜索
   - 历史、用户、流水、审计日志不应长期依赖一次性加载。
   - 原因：规模增长后性能和体验都会下降。

### P1：商业化前需要补

1. 套餐页和订单
   - 用户自助购买积分。
   - 订单状态、支付回调、后台补单。

2. 任务队列
   - 任务状态：排队、运行、成功、失败、取消。
   - 支持刷新后恢复。
   - 后台可看失败率和并发。

3. 资产整理服务端化
   - 文件夹、标签、收藏和历史参考图进入服务端资产索引。
   - 支持跨分页准确筛选和多端同步。

### P2：有价值但暂缓

1. 实时画布
   - 复杂度高，需要专门画布、低延迟模型和任务调度。

2. 视频生成
   - 当前产品链路仍围绕图片，视频会显著扩大存储、计费和任务队列复杂度。

3. 团队协作
   - 需要权限、团队空间、共享资产和审计模型，商业闭环前不优先。

## 需要精简的地方

### 创作工作台

现状：

- 文生图、图生图、对话、工具、编辑入口都集中在 `CreateView.vue`。
- 对新用户来说入口多，理解成本高。

建议：

- 保留顶部模式切换，但每个模式拆成独立组件。
- 高级参数默认折叠，保留当前摘要。
- 工具模式只展示已可用工具，未上线工具不要占主流程。

### 历史资产页

现状：

- 已有搜索、筛选、收藏、标签、文件夹、批量。
- 操作逐渐变多。

建议：

- 卡片只保留：再次创作、复制、整理。
- 删除和下载放在悬浮图标或详情页，避免主操作拥挤。
- 批量模式中保留整理、下载、删除。

### 后台管理

现状：

- 后台能力已经覆盖用户、公告、流水、兑换码、审计。

建议：

- 暂停继续增加后台页面。
- 优先做分页、筛选、导出和操作确认。

## 本轮已处理

- 历史列表增加复制提示词。
- 详情页增加复制参数。
- 再次创作会带回图片比例。
- 工作台 URL 初始化支持更多高级参数：质量、张数、格式、压缩率、背景、审核等级。

## 下一轮建议

按收益排序：

1. 后端 `images` 表增加 generation_params JSON 字段。
2. 详情页展示完整生成参数。
3. 历史列表“再次创作”带回完整参数。
4. 管理后台分页和历史服务端分页。

## 2026-05-24 追加规划与本轮执行

竞品共性：

- Adobe Firefly 用 Style Kits / Boards 把风格参考、生成约束和团队复用沉淀为资产。
- Canva Magic Studio 的竞争力来自 Brand Kit、模板和发布链路，而不是单次生成。
- Midjourney Moodboards / Organize 强调风格板、文件夹、收藏搜索和再次生成。
- Krea Realtime / Enhancer 强调实时迭代和后处理增强；当前阶段先做 Enhancer/Upscale 更现实。
- Ideogram Canvas / Remix / Extend 强调从已有结果继续，而不是每次重新填 prompt。

本轮选择的落地功能：

1. 完整 Remix / 参数复用。
   - 新生成记录保存 `generationParams`。
   - 历史页和详情页“再次创作”回填比例、质量、张数、格式、压缩率、背景和审核。
   - 旧记录缺少参数时按 prompt + ratio 降级。

2. 默认风格要求和常用风格 MVP。
   - 该方向已在 2026-05-26 废弃。
   - 原因：平台不应通过全局风格设置污染每一次生成；用户的风格诉求应留在当前 prompt、参考图或具体创作链路中。
   - 后续不再维护 `stylePrompt`、常用风格模板或参考图组入口。

下一批优先级：

1. 后台列表分页统一：审计、流水、用户管理统一分页体验。
2. 任务队列：生成任务支持排队、运行、失败重试和刷新恢复。
3. 对话链列表优化：服务端按 chain 聚合返回首图和尾图。

## 2026-05-24 资产库性能迭代

本轮已处理：

- 历史记录接口支持 `limit`、`offset`、`mode`、`q`，返回 `total`。
- 历史页搜索和类型筛选改为服务端查询，避免长期只加载前 50 条。
- 历史页新增分页和每页数量切换，默认每页 24 条。
- `images` store 保持 `fetchImages(50)` 旧调用兼容，同时支持对象参数。
- `ImagesRepo` 增加分页 / 搜索测试，覆盖用户隔离、关键词搜索和 offset。

当前取舍：

- 收藏仍保留在当前结果内二次筛选，因为收藏状态目前是本地偏好，不适合强行混入服务端查询。
- 文件夹、标签已进入服务端分页查询，避免当前页内二次筛选导致结果不完整。
- 对话链列表已补全服务端轮次数；详情页和“从此继续”仍可拿到完整链路。
- 后续如需全量准确的收藏筛选，需要把收藏从本地偏好迁移为服务端资产索引。

下一批建议：

1. 对话链列表优化：服务端按 chain 聚合返回首图和尾图，进一步减少前端当前页聚合。
2. 后台分页体验统一：复用同一套 limit / offset / total 交互。
3. 任务队列：生成任务支持排队、运行、失败重试和刷新恢复。

## 2026-05-24 后处理能力迭代

本轮已处理：

- 新增“高清增强”作为后处理工具入口，复用现有图片编辑链路，不新增模型依赖。
- 后端将 `upscale` 归入 `tools` 模式，并固定走高清质量参数。
- 历史详情可从已有结果直接进入高清增强。

底层模型能力判断：

- 当前接口已经支持图片编辑和高质量输出参数，因此可以先用 prompt 约束实现轻量 Enhancer。
- 更强的超分、去噪、锐化强度滑杆需要专门模型或更细粒度 API，暂缓。

## 2026-05-24 常用风格资产迭代（已废弃）

竞品对标结论：

- Midjourney 的 Moodboards 和 Organize 证明“风格参考 + 作品组织”比单次生成更能提升复用。
- Canva Brand Kit 的核心价值是把品牌资产自然带入创作流程。
- Adobe Firefly Boards / Style Kits 更接近团队化资产沉淀，但当前产品先做个人常用风格闭环即可。

原本已处理：

- 常用风格支持保存 1-4 张参考图。
- 偏好设置页新增常用风格模板：电商摄影、头像写真、社媒海报、柔和插画。
- 创作页选择常用风格后，可把参考图带入图生图。
- 历史页和详情页可把结果图加入常用风格参考图。
- 设置页常用风格新增“看相关”，按风格标签进入历史筛选；无标签时按风格名搜索。

2026-05-26 产品复盘：

- 该能力不再保留。原因是“默认风格 / 常用风格”会把平台收窄成固定项目或固定审美工作流，且容易在用户没有明确选择时影响生成结果。
- 保留并继续加强文件夹、标签、收藏、参数复用和参考图上传；这些能力更适合作为通用生图平台的资产层。

## 2026-05-24 对话创作 UI 迭代

竞品对标结论：

- Ideogram Canvas / Remix 强调从已有结果继续，而不是重新填写一套表单。
- Firefly / Canva 的生成入口通常把“当前上下文、参考图、参数”收敛在输入区附近。
- 对话式创作要像一个会话工作台：左侧是会话，不是提示词列表；右侧是当前轮次、来源图和本轮改动。

本轮已处理：

- 对话创作左侧保持真正会话列表：新建、选择、删除当前会话。
- 主区域顶部增加当前会话标题、轮次、参数摘要和来源图状态。
- 上传参考图后会立即显示上下文预览，并且优先生效于本轮对话生成。
- 对话底部保留比例、质量、张数、格式、背景、审核、压缩率等完整配置，不追加任何全局风格要求。
- 底部比例、质量、张数、格式、背景、审核、压缩率保留完整配置，但视觉收敛为轻量工具条。

底层模型能力判断：

- 连续对话继续复用现有 `continueDialogue` 接口。
- 参考图通过现有图生图链路进入当前任务，不通过常用风格资产间接注入。
- 参考图优先生效修复为前端上下文选择逻辑，不改变 API。

下一批建议：

1. 任务队列：生成任务支持刷新恢复、失败重试、取消和状态追踪。
2. 收藏服务端化：收藏状态进入用户级资产索引，支持跨分页准确筛选。
3. 对话链服务端聚合：历史列表按 chain 返回封面、最后一轮和完整轮次数，减少前端聚合。

## 2026-05-26 历史筛选服务端化迭代

本轮已处理：

- `GET /api/images` 支持 `folder` 和 `tag` 查询参数，和 `limit`、`offset`、`mode`、`q` 组合使用。
- `ImagesRepo.listByUserPaged` 支持文件夹精确筛选、未归档筛选、标签精确筛选、未打标签筛选。
- 标签筛选使用 SQLite `json_each` 精确匹配 JSON 数组元素，并通过 `json_valid` 兼容异常历史数据。
- 历史页切换文件夹或标签时重置页码并请求服务端，不再只过滤当前页结果。
- 历史页筛选选项会保留当前选中的文件夹 / 标签，避免服务端当前页为空时选项消失。
- `images` store 的 `fetchImages` 保持旧数字参数兼容，同时记录 `folder` 和 `tag` 到 `lastQuery`。
- 仓储测试覆盖文件夹、未归档、标签、未打标签和用户隔离。

底层模型能力判断：

- 该能力是资产库查询与分页一致性优化，不依赖图像生成模型能力。
- 没有改变生成、编辑、对话创作接口。

当前取舍：

- 收藏筛选仍在前端本地执行，因为收藏状态当前保存在偏好设置里，不在服务端资产表。
- 对话链仍在历史页当前页内合并展示，但轮次数已经由服务端返回。

下一批建议：

1. 收藏服务端化：让收藏支持跨分页准确筛选和多端同步。
2. 任务队列：生成任务支持刷新恢复、失败重试、取消和状态追踪。
3. 对话链服务端聚合：列表接口直接返回 chain 卡片，减少前端聚合逻辑。

## 2026-05-24 常用风格参考图迭代（已废弃）

- 常用风格支持从内置模板快速预填名称、说明、比例、标签和风格要求，降低新用户配置成本。

- 历史列表支持单张或批量把结果图加入常用风格参考图。
- 参考图支持外链和站内 `/uploads/` 图片，避免历史资产无法复用。
- 该能力复用当前图生图底层链路，已有实现支持 1-4 张参考图，因此没有新增模型假设。

- 不再保留常用风格参考图集合。
- 参考图仍然重要，但应作为当前创作、图生图、对话续作或历史复用的一部分，而不是被存成全局常用风格。

- 内置模板只是本地表单预填，不调用模型，不改变生成接口；底层模型能力要求为 0。

## 2026-05-26 默认风格 / 常用风格下线

产品判断：

- 不需要默认风格和常用风格。
- 默认风格会隐式改写用户提示词，风险高于收益。
- 常用风格会把通用生图平台错误地引向“项目 / 品牌风格沉淀”工作流，不适合作为默认能力。

本轮处理：

- 偏好设置只保留比例、质量、张数、格式、背景、审核和压缩率。
- 创作页、对话创作、历史页、详情页移除常用风格入口。
- 生成请求不再追加全局 `stylePrompt`。
- 保留文件夹、标签、收藏、服务端筛选和参数复用能力。

后续方向：

1. 任务队列：刷新恢复、失败重试、取消、运行状态。
