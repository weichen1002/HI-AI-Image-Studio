# 对话创作工作流改造方案

日期：2026-05-24

## 结论

当前“对话创作”不应该继续做成普通参数表单。它的核心价值是围绕同一张图逐轮修改，所以更适合独立成“对话式改稿工作台”：

- 左侧保留对话轮次、起始图片和上下文状态。
- 中间聚焦当前结果图和本轮要求。
- 底部固定输入栏，用自然语言描述下一轮修改。
- 参数只保留对对话生成有效的比例、质量和背景策略。

本轮已按这个方向落地前端，不改后端接口，避免扩大风险。

## 现状问题

原实现虽然支持连续对话，但交互仍是“左边填表，右边预览”：

- 历史轮次和当前结果割裂，用户不容易理解这是同一条创作链。
- 本轮输入像一个表单字段，不像对图片继续提出修改要求。
- 上传起始图、用结果继续、断开上下文都堆在表单里，决策成本偏高。
- 全局提交按钮在对话模式里语义弱，不像“发送下一轮修改”。

## 改造范围

本轮改造限定在 `src/views/studio/CreateView.vue`：

- 对话模式使用独立布局，不再复用普通创作左右分栏。
- 文生图、图生图、工具模式保持原布局。
- 复用现有状态和接口：`continueDialogue`、`fetchDialogueHistory`、`dialogueMessages`、`dialogueSourceImage`。
- 发送成功后清空输入框，画布保留最新轮次要求和结果。

## 新工作流

1. 用户进入“对话创作”。
2. 可以空白开始，也可以上传起始图片，或使用最近生成结果继续。
3. 用户在底部输入栏描述本轮修改。
4. 系统生成新结果，并将新结果作为下一轮上下文。
5. 左侧轮次列表保留最近修改记录，点击可复用某一轮 prompt。

## 后续建议

后端已经能支撑基础对话式改图，但平台化还缺 3 个能力：

- 对话链列表：现在左侧只显示当前链路最近几轮，后续应支持切换历史对话链。
- 轮次结果缩略图：每轮记录应展示对应结果图，便于回到某个版本继续。
- 参数持久化：需要保存每轮的比例、质量、背景、来源图和模型信息，方便复用和审计。
