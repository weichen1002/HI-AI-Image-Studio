# 创作工作台重构与对话创作设计

## 背景

当前工作台已经具备：

- 一次性文生图
- 一次性图生图
- 多参考图上传
- 质量档位、张数、格式、压缩率、背景策略、审核等级
- 局部重绘
- 扩图
- 抠图入口

但产品结构仍然存在根本问题：

- 生成、连续对话、工具被混在一起
- “连续改图”这个命名太窄，无法覆盖“从空白开始对话创作”或“带图开始对话创作”
- 普通用户无法快速理解：自己现在是在“一次性生成”、还是“对话创作”、还是“工具处理”

用户最终确认的关键判断是：

- 顶层不应再是 `文生图 / 图生图 / 连续改图 / 工具`
- 更合理的顶层应为：`一次生成 / 对话创作 / 工具`
- `一次生成` 里面再分 `文生图 / 图生图`
- `对话创作` 是独立模式，可以从空白、参考图、已有结果三种起点进入
- `局部重绘 / 扩图 / 抠图` 是工具，不属于对话创作
- 对话创作需要“最近几轮对话要求”的小历史区，而且这段历史需要持久化
- 小历史按“对话链路”归属，而不是只挂在当前单张图片上

## 已确认范围

本次设计覆盖：

- 重新定义工作台顶层结构
- 把 `连续改图` 升级为更准确的 `对话创作`
- 重新定义 `一次生成`、`对话创作`、`工具` 三块的边界
- 设计对话创作的小历史区
- 设计对话创作历史的持久化方案

## 非目标

- 本次不拆新的左侧一级菜单
- 不单独新增“工具中心”页面
- 不在本次文档里展开流式阶段图的协议细节
- 不在本次文档里展开 Responses API 全量实现细节
- 不同步重构管理中心

## 目标

- 让用户一眼理解当前是在做哪种事
- 保留“快速一次出图”的简单路径
- 提供真正独立的“对话创作”模式
- 把工具从创作流程里拆开
- 为后续多轮上下文和链路历史打下清晰的数据结构

## 方案对比

### 方案 A：`一次生成 / 对话创作 / 工具`

顶层三个主模块：

- `一次生成`
- `对话创作`
- `工具`

优点：

- 结构最稳定
- 普通用户和高级用户都容易理解
- `对话创作` 不再被错误理解成“基于结果继续修一下”
- 工具与创作明确分开

缺点：

- `CreateView` 需要重新组织成三套不同工作区

### 方案 B：`文生图 / 图生图 / 对话创作 / 工具`

优点：

- 保留原有术语
- 用户容易直接看到文生图和图生图

缺点：

- 顶层项过多
- `文生图 / 图生图` 和 `对话创作` 的层级关系不自然

### 方案 C：`对话创作 / 工具`

优点：

- 极简
- 长期最先进

缺点：

- 对当前用户心智跳跃太大
- 会牺牲“一次生成”的快捷路径

### 结论

采用方案 A。

原因：

- 它既保留了“一次生成”的低门槛入口
- 又把“对话创作”从旧的连续改图概念里解放出来
- 还把工具保持为独立模块，避免再次混乱

## 信息架构

### 顶层结构

`CreateView` 调整为：

1. 工作台标题区
2. 顶部主模块切换
3. 当前模块对应的左侧工作区 + 右侧预览区

顶部主模块固定三项：

- `一次生成`
- `对话创作`
- `工具`

### 一次生成的子模式

`一次生成` 不是单一表单，而是再分两个子模式：

- `文生图`
- `图生图`

它们共享同一套生成参数体系，只在“是否需要上传参考图”上不同。

### 对话创作的定义

`对话创作` 是独立模式，不等于“连续改图”。

它可以从三种起点进入：

- 空白开始：用户直接通过多轮对话生成第一张图
- 带图开始：用户带一张参考图进入对话创作
- 基于已有结果开始：用户从某张历史结果继续对话

核心心智：

- 用户不是“一次性写完全部提示词”
- 而是“像聊天一样逐步把图做对”

### 工具的定义

`工具` 只负责明确图像操作：

- `局部重绘`
- `扩图`
- `抠图`

工具不承担连续对话创作逻辑。

## 页面内容设计

### 一次生成

显示内容：

- 子模式切换：`文生图 / 图生图`
- 提示词
- 参考图上传（仅图生图）
- 图片比例
- 常用设置
- 进阶设置
- 主按钮 `生成图片`

页面原则：

- 让第一次使用的人最快出第一张图
- 保持极简核心

### 对话创作

显示内容：

- 对话起点区
  - 空白开始
  - 参考图开始
  - 基于已有结果开始
- 当前基底图预览（如果当前链路已有图）
- 对话输入框
- 最近几轮对话要求的小历史区
- 主按钮 `继续生成`

页面原则：

- 它是独立创作模式，不复用“一次生成”那套完整参数布局
- 用户看到的重点应是“对话上下文”和“最近几轮要求”
- 不默认平铺格式、压缩率等高级生成参数

### 工具

显示内容：

- 来源图区
- 工具选择区
- 工具说明
- 工具要求输入
- 主按钮按工具变化

## 参数放置规则

### 一次生成展示的参数

保留：

- `生成质量`
- `一次生成`
- `输出格式`
- `压缩率`
- `背景策略`
- `审核等级`

原因：

- 这些都属于一次性生成的常用或高级参数

### 对话创作默认不展示的参数

默认不展示：

- 一次生成张数
- 输出格式
- 压缩率
- 背景策略
- 审核等级
- 快捷预设

原因：

- 对话创作的主心智是“多轮调整”
- 不应让用户再次落回大块参数表单

如后续确有需要，也应以更轻量的“补充设置”方式加入，而不是首屏平铺。

### 工具不展示的参数

工具不展示“一次生成”那套常用/进阶设置。

原因：

- 工具处理的是操作逻辑，不是一次性生成参数

## 对话创作小历史区

### 目标

小历史区的作用是让 `对话创作` 看起来像独立模式，而不是一次性输入框。

### 展示内容

默认展示最近 3 到 5 条对话要求。

每条展示：

- 要求内容
- 时间
- 当前链路中的先后顺序

可选交互：

- 点击某条要求，带回输入框继续修改

### 写入规则

- 只有一次对话创作成功生成后，才写入一条历史
- 失败的输入不写入正式历史

## 对话历史的数据结构

### 结论

对话创作历史不应直接塞进图片表。

采用：

- 图片记录表新增 `continuationChainId`
- 新增独立的对话创作链路消息表

### 推荐结构

图片记录保留：

- `id`
- `sourceImageId`
- `continuationChainId`
- 其他现有图片字段

新增对话创作消息表，建议字段：

- `id`
- `chainId`
- `imageId`
- `parentImageId`
- `prompt`
- `createdAt`
- `createdBy`

### 归属规则

小历史按“链路”归属，而不是按“当前单张图”归属。

示例：

- A 通过对话创作生成 B
- B 再通过对话创作生成 C
- B 和 C 的对话要求属于同一条对话链

如果用户切换了来源图，且来源图不属于当前链，则新开一条链。

## 视觉与交互原则

### 1）三块工作区要长得不一样

要求：

- `一次生成` 像轻量生成表单
- `对话创作` 像对话式创作区
- `工具` 像操作型工作区

### 2）对话创作不要再叫“连续改图”

原因：

- “连续改图”只覆盖“基于已有结果继续改”
- 无法覆盖“从空白开始对话创作”或“带图开始对话创作”

### 3）更多菜单只留低频动作

只保留类似：

- `重置预览`

不再承载主流程入口。

## 迁移策略

### 阶段 1：修正顶层结构

- 顶部改为 `一次生成 / 对话创作 / 工具`
- `一次生成` 下再分 `文生图 / 图生图`

### 阶段 2：能力重新归位

- 文生图、图生图归入 `一次生成`
- 局部重绘、扩图、抠图归入 `工具`
- 原“连续改图”概念迁移为 `对话创作`

### 阶段 3：对话创作链路落地

- 接入对话链路数据结构
- 写入和读取最近几轮对话要求
- 后续再考虑与 Responses API 多轮上下文进一步打通

## 状态管理要求

### 一次生成

- 文生图与图生图之间尽量保留提示词
- 图生图的参考图离开模式后不误清

### 对话创作

- 对话输入单独管理
- 对话链路来源单独管理
- 不与一次生成的提示词强绑

### 工具

- 工具来源图单独管理
- 不与对话创作链混用

## 错误处理

- 对话创作没有任何起点时，允许从空白开始，不应强制要求已有结果图
- 对话创作链路读取失败时，仍允许当前输入，但要提示历史暂不可用
- 工具没有来源图时，明确提示“请先选择图片”

## 测试与验证

至少验证：

- 一次生成的文生图正常
- 一次生成的图生图正常
- 顶层切换后只展示对应内容
- 对话创作可从空白开始
- 对话创作可从参考图开始
- 对话创作可从已有结果开始
- 对话创作成功后会写入链路历史
- 工具模块的局部重绘、扩图、抠图不回归

## 定稿结论

最终采用以下结构：

- 顶部主模块为 `一次生成 / 对话创作 / 工具`
- `一次生成` 下再分 `文生图 / 图生图`
- `对话创作` 是独立模式，不再使用“连续改图”命名
- `工具` 只承载局部重绘、扩图、抠图
- 对话创作的小历史区按链路持久化

这版设计的重点不是再换一个名字，而是把工作台稳定成三种完全不同的用户任务：

- 快速一次出图
- 连续对话创作
- 明确工具处理
